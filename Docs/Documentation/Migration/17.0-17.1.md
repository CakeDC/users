# Migration Guide from 17.0 to 17.1

Version 17.1 moves Webauthn two-factor authentication to `web-auth/webauthn-lib` 5.3.13 or higher.
Every webauthn-lib release before 5.3.13 is affected by published security advisories, including
forged packed/TPM attestations, username enumeration through fake credentials and metadata checks
that skip the trust path. Webauthn 2FA otherwise works as in 17.0, except for the algorithms and
cross-origin cases described below.

## Version Requirements

- PHP **8.2 or higher**
- CakePHP **5.3 or higher**
- `web-auth/webauthn-lib` **5.3.13 or higher**, when Webauthn 2FA is used. The plugin declares a
  conflict with older versions.

Update the library in your application:

```
composer require web-auth/webauthn-lib:^5.3.13
```

## Stored Credentials

Credentials saved in `users.additional_data.webauthn_credentials` by 17.0 keep working: users do
not have to register their security keys again.

A user who is in the middle of a Webauthn registration or login while you deploy has to start it
again, because the options kept in the session were created by the old library.

## Algorithms

Registration no longer offers the non-standard `Ed256` (-260) and `Ed512` (-261) algorithms, which
no WebAuthn authenticator uses; cose-lib 5 will refuse them. A security key registered with one of
them would stop working.

## Cross-Origin Pages

webauthn-lib 5 rejects a Webauthn response that the browser marks as cross-origin (it has a
`topOrigin`). If your application shows the Webauthn 2FA page inside an iframe of another origin,
registration and login fail there. Show the page in its own window, or at the top level of your site.

## API Changes

These changes only matter if your application extends or calls the classes in
`CakeDC\Users\Webauthn` directly:

- `RegisterAdapter::verifyResponse()`, `AuthenticateAdapter::verifyResponse()` and the methods of
  `UserCredentialSourceRepository` use `Webauthn\CredentialRecord` instead of
  `Webauthn\PublicKeyCredentialSource`.
- `UserCredentialSourceRepository` no longer implements `Webauthn\PublicKeyCredentialSourceRepository`,
  which webauthn-lib 5 removed.
- `CakeDC\Users\Webauthn\PublicKeyCredentialLoader` no longer extends the library loader. It takes a
  Symfony serializer in its constructor, and `loadArray()` is its only method: the inherited
  `load(string)` is gone.
- `AuthenticateAdapter::createAssertionResponseValidator()` was removed. Validators are built from
  `BaseAdapter::createCeremonyStepManagerFactory()`.
- Options are sent to the browser as JSON by `BaseAdapter::serializeOptions()`. `json_encode()` no
  longer works on webauthn-lib 5 option objects.
- The session keys `Webauthn2fa.registerOptions`, `Webauthn2fa.userEntity` and
  `Webauthn2fa.authenticateOptions` hold JSON strings written by the webauthn serializer, not objects.
